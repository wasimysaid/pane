# Let the host watch the clipboard and keep its history for an extension

Proposed 2026-09-29 by the implementation of #35; not yet confirmed by the user. Clipboard history is an optional, disableable default extension ([ADR 0001](0001-small-core.md), Q6), off until the user turns it on, and disabling it must stop host-managed observation (US66, US70). A WASI 0.3 guest cannot see the system's clipboard, and running the extension on every copy would contradict lazy activation ([ADR 0005](0005-lazy-activation-and-managed-dependencies.md)); expiry must also work without running the extension (#36).

So the host provides clipboard history as an extension API, `pane:extension/clipboard-history`, and keeps the history itself as the calling package's extension data, of a kind of its own (`clipboard-history.json`, a versioned, typed file counted as saved data, readable only by the user: mode 0600 on Unix, a protected DACL for the user and SYSTEM on Windows). The host watches the clipboard exactly while some installed package's history is on and the package's generation runs, which it learns from the extension data's generation changes, so disable, Pane's pause and uninstall stop the watch without the extension or the launcher doing anything more. What is kept is decided by one platform-neutral rule (plain text, bounded size and count, one item per text, the copying application's sensitive markers, programs the user excluded); each system contributes only an adapter that reports changes with their markers and owner. The extension, the Clipboard History default extension in Rust (with JavaScript and TypeScript samples of the same contract), only shows the controls and the items.

As for applications ([ADR 0015](0015-host-finds-and-opens-applications-for-an-extension.md)) and hotkeys ([ADR 0016](0016-host-registers-global-hotkeys-for-commands.md)), a native helper ([ADR 0014](0014-optional-native-extension-helpers.md)) was not used: the host already runs natively, and a helper's process would have to run all the time to watch. Keeping the history in Pane's own record (like `hotkeys.json`) was not used either, since it is the extension's durable content, whose keep/delete choice on uninstall and retained data must apply to it. Letting the guest store it in its `content` was not used, since the host must write it while the guest does not run and the extension owns its content's keys.

Windows watches with a clipboard format listener on a message-only window of a thread of Pane's own; only that thread reads the clipboard. Stopping never waits more than a moment on a read stuck on the copying program: Pane fences the watch's reports before it stops the thread, and leaves a stuck thread to end on its own. A read that began before a Clear is dropped too. macOS (#37) and Linux (#38) have no adapter yet, so the package declares Windows only and is explained as unavailable there through #19's mechanism. Still open: finite retention and the remaining deletion controls (#36), and the macOS and Linux adapters.
